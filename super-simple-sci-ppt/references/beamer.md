# Beamer 规范

## 模板与内容

续作以用户实际修改的 TeX/PDF 为底稿。新建 Beamer 默认使用 Metropolis + ctex、16:9 体系，使用 `assets/beamer-template.tex`，再按内容补充。

- 保留模板自身的标题、正文、公式、caption 和页码字号；不套用 PPTX 的 32/24/16 pt。
- 模板的正常图注和数学上下标可以采用较小字号。这不授权新增纠错、免责或脱离正文的小字旁注，也不授权把正常正文缩成小字塞版面。
- `图N：说明` 使用真正的 `figure` 和 `caption`；必要图例、单位与色标保留。优先放大证据图，不凭空规定图幅比例。
- 原有汇报中的目录、Metropolis 章节页和无标签 takeaway 可以保留，但不是每次必备。短文献汇报可以直接开始文章或方法介绍。
- 已有 takeaway 只写实际内容，不加“要点：”“结论：”等模板标签；不能将其推广为每页固定结论栏。
- 单篇文献在首页集中文章标题、作者及期刊信息。方法叙述保留必要公式与变量含义，详略按听众和本次修改范围决定，不自动压成三页或扩成教材。
- 图像、引用与科学判断遵守共同规则；既有代码只作为实现材料，不把其所有样式和句子视为用户认可。

## 工程与编译

保留入口、递归 `input/include`、图片、bib、局部样式依赖及相对路径。使用源码声明和必要构建依赖查闭包；不能只复制主 TeX 和 PDF。若跨工程引用资料，仅带实际依赖，不复制整个计算目录。

在已安装 TeX 工具链的环境，从主文件所在目录运行；Windows 可在 WSL 内进入该目录：

```text
latexmk -synctex=1 -interaction=nonstopmode -file-line-error -xelatex -outdir=build -auxdir=build main.tex
```

所有输出和辅助文件进入入口旁 `build/`，不另造 `build_beamer/`。在 Windows 路径中含空格、中文时明确设置工作目录，不拼接不安全 shell 字符串。沿用当前环境已有字体；替代字体须核对渲染并如实记录。

## 验收与交付

检查引用、缺字、缺图、未定义控制序列、overfull 和页数。渲染最终 PDF 的每一页并查看，不能把旧 PNG 数量当当前页数；编译成功或无 overfull 也不能代替视觉检查。

归档原件不改写。必要路径修正放在工作副本并说明。默认交付可继续编译的工程与 PDF；不把 article 报告误归为 Beamer，也不把参考者的报告归为本人作品。
