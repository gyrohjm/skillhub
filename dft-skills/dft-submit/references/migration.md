# 跨集群迁移

用于换集群重算、迁移未运行分支、从稳定检查点续算。迁移是建立新的运行实例，不是移动或覆盖源目录。资源默认值见 [clusters.md](clusters.md)，运行依赖按所选集群的本地私有说明核对。

## 1. 确定任务与源状态

记录源集群、绝对目录、作业 ID、计算阶段、目标集群及绝对目录。查询源端 `squeue`、`sacct` 和程序日志，区分待提交、排队、运行、失败、完成及科学验收状态。

- 默认迁移稳定输入并从头计算；续算须明确检查点、生成版本和配套文件。
- 正在写入的波函数、密度、轨迹或 `.save` 目录不能直接作为一致检查点。使用已完成阶段的不可变副本；确需停源作业时采用程序支持的停止方法，等待退出并检查文件完整性。
- “迁移”本身不授权取消源作业。用户已经明确要求停止/取消时执行并记录；否则保留源任务，在目标提交前说明源仍活动的重复计算风险并确定处理方式。明确授权的并行对照计算可两端运行。
- 分流扫描/声子位移时记录具体叶节点列表，保留已完成且验收合格的结果。父任务完成状态不能替代叶节点检查。

完成条件：迁移对象、源状态、目标路径、重算/续算方式及已有授权明确。

## 2. 在目标端重新适配

使用配置别名连接，先执行只读查询（以下在目标远端执行）：

```bash
hostname
id -un
sinfo -N -o '%N %P %c %m %G %t'
scontrol show partition 分区名
scontrol show node 代表节点名
```

核对分区、账户/QOS、节点类型、物理核数、可用内存和存储配额。节点拓扑中的 Sockets × CoresPerSocket 与调度器可分配资源应一致；ThreadsPerCore > 1 时不直接把 `%c` 当物理核数。不凭登录节点硬件或瞬时空闲数量改科学参数。

资源默认值和个人并行策略从本地私有环境资料读取，不把某一集群的核数、分区或启动器作为通用默认。同步节点数、MPI ranks、线程数、绑定和应用并行参数；不能只修改分区名。资源和限时以当前明确要求及所选环境为准。

优先目标端已安装、与源任务兼容的版本。查 `module list`、`command -v`、可执行文件真实路径和 `ldd`；launcher 与程序必须使用同一 MPI 栈。`srun` 需匹配目标程序的 PMI/PMIx 支持，不能机械替换 `mpirun`。CPU 指令集、OS/glibc、GPU 架构均需匹配。无合适软件时报告缺口；安装或更换科学方法不是迁移的隐含步骤。

## 3. 决定携带哪些文件

| 类型 | 携带与检查规则 |
|---|---|
| 科学输入 | 结构、约束、泛函、赝势/基组、截断能、网格、磁性/SOC、收敛阈值保持含义一致；保留 Selective dynamics |
| 外部依赖 | 解析绝对路径、相对路径和软链接；核实目标可读、许可证允许使用的同一数据，记录 SHA-256，不能只比文件名 |
| VASP 续算 | CONTCAR 作为新 POSCAR 时记录来源；WAVECAR/CHGCAR 按版本、精度、晶胞、k 点、自旋和任务模式验证，协调 ISTART/ICHARG，不能盲拷 |
| QE/EPW 续算 | 核对 prefix/outdir、完整 `.save`、波函数及阶段依赖；PH/EPW 还可能需要 dvscf、动力学矩阵和 Wannier 数据。不同版本/并行布局兼容性不明时重建所需上游阶段 |
| ABACUS/OpenMX/SIESTA | 版本、计算模式、轨道/赝势和 restart 文件成套匹配；软件间结构转换不等于续算兼容 |
| 旧输出/运行状态 | 留在源端或只作明确标注的证据；旧 Job ID、日志、完成标记、锁文件不成为目标新运行的有效状态 |

目标软件缺少原任务特制功能（如 relax-xy、VTST 或 GPU 构建未启用的接口）时，不能换成普通版本宣称等价。必须改变版本、赝势或科学设置时，写明差异和影响，重新评审受影响部分。纯路径/资源适配保留相同科学输入身份，但生成新的执行记录。

## 4. 传输、校验与记录

在目标建立不覆盖已有结果的新目录，使用目标项目的 `calculations/<composition>/<structure>/<task>[/<variant>]/` 规范；任务身份与源任务不同，lineage 保留来源。目标已存在时先核实归属和内容；不使用 `rsync --delete` 或覆盖式镜像。

1. 按明确文件清单在源端生成稳定快照和 SHA-256 清单；快照前后文件应不再变化。清单包含输入、依赖及选中的检查点，保留文件相对路径。
2. 支持两端直连时使用实际已配置的连接；本地 SSH 别名通常不在远端有效。不能直连时经本地临时目录两段 `scp`/`rsync`，也可用已验证支持的 `scp -3`。Windows 没有 rsync 时使用 scp；不复制凭据、不临时修改 SSH 配置。
3. 目标按清单重新计算 SHA-256；输入以二进制方式复制。只有提交脚本需规范为 LF，科学输入不做批量编码/换行转换。软链接明确解析或改为目标路径，避免悬空链接。
4. 科学输入保持源哈希；目标路径或并行参数发生必要变化时，保存差异及目标最终哈希。校验传输版本后再校验适配后的最终版本，不将两者混为同一哈希。
5. 新运行记录至少保存：源/目标集群和目录、源/目标作业 ID、阶段或叶节点、源输入/检查点哈希、目标输入哈希、软件版本与环境路径、资源配置、改动理由、重算/续算方式、授权范围和时间。可复用项目现有 receipt/ledger，无需另建第二套状态库。

若使用 dft-workflow，按其当前 CLI 重新准备目标草稿并进行目标资源预检；旧 preflight/approval 缓存不能跨集群复用。审批只更新受迁移影响的范围，已有明确提交授权仍有效。工作流不支持该目标时说明限制，不能把某个集群专用 profile 改名伪装为其他集群。

完成条件：清单传输无遗漏，哈希匹配，目标路径有效，源和目标运行来源可以追溯。

## 5. 检查、提交与验收

从目标模板制作任务副本并读全文，执行 `bash -n`；资源变化时执行 `sbatch --test-only`。两者不能证明 MPI 实际启动、版本兼容或科学正确。首次使用新组合时，在已授权计算范围内验证真实输入启动、rank 数、线程绑定及内存；若必要冒烟超出既有授权，先给出具体算例和资源范围。

用户已要求将具体任务转至目标集群计算且输入、目录、资源齐备时，按已有授权提交，不重复确认。仅要求写流程或搬文件时不提交。提交前重新查源/目标队列和运行记录，处理源仍活动的情况；在目标目录执行 `sbatch --parsable <software>.sh`。提交返回不明确时先查询，不盲目重试。

记录目标真实 Job ID；目标依赖必须映射成目标集群作业 ID，不能复用源端 `--dependency=afterok:<id>`。跨集群依赖以源阶段产物验收和传输完成为门，不用 Slurm ID 直接连接。

按顺序检查调度器状态/退出码、应用正常结束/产物完整、电子与离子收敛及任务科学判据。版本或硬件变化时，用适合任务的能量/力/应力等容差评估，不能要求普遍逐位一致，也不以退出码代替结果比较。完成后更新目标记录，源记录保留；不自动清理源目录或检查点。
